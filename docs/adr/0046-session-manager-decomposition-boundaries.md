# SessionManager decomposition boundaries: AgentAccessPolicy dual projection, symmetric assembler I/O, typed event stream, and SseChannel

The SessionManager in `server/agent_runtime` (about 2900 lines, nearly a hundred methods) physically crammed six unrelated responsibilities into one class: access and sandbox rules, SDK options assembly, subscription broadcasting, token/cost extraction, session lifecycle, and message serialization. The replay-boundary state machine leaked into the consumer AssistantService (decoding the `_replay_done` / `_idle` / `_queue_overflow` sentinels), access rules could only be tested by monkeypatching private methods, and subscription broadcasting was implemented twice, here and in the project event service. We decided to extract independent modules by responsibility, each with a small interface and a deep implementation, with the following boundaries: **AgentAccessPolicy**, a single class, carries the source of truth for the rules of "what the agent may touch", and projects the same rules two ways — compiling settings for the kernel sandbox layer, and providing per-call read/write/command verdicts for the application-layer hooks; it does zero I/O and is purely constructed from process-level root paths; the Windows degradation (Bash prefix allow-list) is contained within the class via a `sandbox_enabled` constructor parameter; Bash secret stripping belongs to this class (the wrapping and allow-list matching are mutually coupled and must be kept local); it outputs only pure verdicts, while SDK wrapping and permission-chain ordering stay in a thin adapter on the session-management side (the SDK is an optional dependency, and the check for its absence exists only in the adapter). It is not named SandboxPolicy — the glossary reserves "agent sandbox" for the kernel-level isolation layer, and this module also serves application-layer hooks that are not part of the sandbox. The **options assembler** is a class that holds dependencies and is allowed I/O; credential injection (DB → SDK subprocess env, a transport concern rather than leftover config) is its responsibility; its I/O decision follows the same criterion as AgentAccessPolicy's — static rules do zero I/O, while assembly, whose job is to collect things on the spot when a session opens, is allowed I/O. **Typed event stream**: SessionManager keeps a single async context manager for the message stream to AssistantService, and its output becomes semantic events (replay batch delivered once → live items one by one → heartbeat → overflow ends the stream, and stream end is the reconnect signal), with the atomic hand-off between replay and subscription pulled back inside the seam; this decision re-evaluates the ban in `docs/adr/0005` on "don't start a separate typed event system" — that ban's context was an unchanged seam with consumers decoding sentinels; once the seam is redrawn, typed events are the natural form for absorbing the sentinels; the core of 0005 (CM form, `is_disconnected` self-check, `__aexit__` cleanup backstop) is kept as-is, and its wording about sentinel consumption is revised along with the implementation. **SseChannel** consolidates subscription broadcasting for the session stream and the project event stream: its responsibilities are limited to subscribe/unsubscribe, broadcast, idle heartbeat, and overflow handling (strategy parameterized: drop non-critical messages one by one + overflow signal vs. remove the subscriber), with optional first/last-subscriber lifecycle hooks; the opening (buffered replay / initial snapshot) is not part of the component, and atomicity is guaranteed by the consumer holding a lock; the deprecated task-stream endpoint (database polling) is not wired in. Token/cost extraction and message serialization are extracted as pure-function modules; session lifecycle, capacity eviction, and patrolling interlock and share the session table and locks, so they stay in the SessionManager core; SessionActor is not changed by a single character (`docs/adr/0028`). Apart from removing the environment-variable fallback for provider base_url, the decomposition is a pure structural reorganization, and behavioral semantics are preserved verbatim.

## Explicitly not adopted

- **Splitting the Windows degradation into a platform adapter** (favored by the architecture review report): rejected. The two platforms' output shapes are asymmetric — the kernel route produces one startup configuration (and lets go of Bash at runtime), the degraded route produces per-call verdicts at runtime — forcing them into the same adapter interface yields an abstraction where each side has half no-ops; and the path rules they genuinely share are identical on both platforms, so after splitting a third shared core would be needed to carry them. Expressing the platform difference with one boolean branch is more honest than two half-empty adapters. Future reviews proposing an adapter split should take this as the ruling.
- **Making AgentAccessPolicy a set of pure functions**: each function would need 5+ root-path parameters, the signatures explode, and callers would still have to gather the parameters themselves — the complexity just moves from inside the class to the call sites.
- **SseChannel including the opening** (calling back an "opening producer function" on subscribe): buffered replay and an on-the-spot scan snapshot share not a single line of implementation; parameterizing them is a false abstraction — the component gets no deeper, it just gains a forwarding layer.
- **Splitting the stream interface into two calls** (first get the replay list, then subscribe to live): messages leak between the two calls; the motivation for the single-stream design is precisely that replay and subscription hand off seamlessly under the same lock; closing the gap would require passing a cursor or sharing a lock across calls, making the interface more complex.
- **Merging credential injection into AgentAccessPolicy** (classified as "both are secret hygiene"): classifying by dependency shape beats classifying by ADR theme — injection reads the DB, stripping does zero I/O; putting them in one class would destroy the foundation of the latter being purely constructible and testable.

## Consequences

- AssistantService no longer knows about any sentinel; in-band sentinels are demoted to an internal mechanism of SseChannel. `docs/adr/0005` is revised in step when the typed event stream lands (describing the current state, without leaving a patch-style supersession chain).
- Access-rule tests move from monkeypatching private methods/environment variables to feeding constructor parameters and asserting allow/deny; during migration the assertions are kept verbatim, and redundancy cleanup is deferred as a separate step.
- The environment-variable containment of provider secrets (startup assertion, empty-value override, Bash stripping) is classified as a permanent mechanism — both its causes, "transport" (the SDK subprocess only accepts env authentication) and "containment" (the parent process environment is external input), do not disappear with DB-based configuration, and it must not be cleaned up as technical debt.
- GLOSSARY.md includes an AgentAccessPolicy entry, whose _Avoid_ notes SandboxPolicy.
