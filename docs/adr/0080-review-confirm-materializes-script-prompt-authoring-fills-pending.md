# Content confirmation turns the script plan into the formal script; prompt authoring only fills storyboards pending authoring

`docs/adr/0041` made the script plan the persistent substrate of content: the formal script is its projection plus a visual layer, prompt authoring merges incrementally by entry fingerprint, and the set and order of entries follow the script plan. The cost is that the content of one episode is persisted twice, while structural editing already happens downstream: the agent's `patch_episode_script` insert / remove, adding and deleting units on the reference-to-video canvas, and the add/remove storyboards planned for the timeline all modify the formal script directly, and the next prompt authoring run, merging by the plan's set, silently reverts those changes; editing the plan on the content confirmation page after authoring is done sends the whole episode back to pending confirmation, blocking users who are working on the timeline; and the whole machinery of fingerprints, backfill of existing data and `splice_entries` merging exists only to keep the two copies in sync. We decided that **after prompt authoring is complete, the formal script is the single source of truth for that episode's content; the script plan is a one-time input and retires at the moment of content confirmation**.

- **Content confirmation materialises.** The confirm action mechanically converts the script plan into a whole-episode formal script, reusing the existing mechanical conversion, but only whole and only at confirmation; the two conversion modes, set synchronisation and "explicitly adopt new content", are retired. If the episode already has a formal script, confirmation overwrites it: all old storyboards are treated as removed, their artifacts are handled per the storyboard-removal rules, and prompts hand-edited by the user are discarded too; the confirmation dialog is shown as danger and lists the storyboards that will be removed and where their artifacts go, and confirmation on the agent side goes through the same service and likewise refuses to overwrite without confirmation. Redoing a whole episode is therefore just "re-run the script plan, then confirm", with no other mechanism needed. The drama scene description (free-text visual adaptation) moves into the formal script's `scene_description` together with the content, serving as input to the "visual adaptation" line of prompt authoring, since authoring no longer reads the script plan and can only get it from here; this field is hidden from the LLM output schema, not shown on the timeline, not modifiable via PATCH, and not exposed to creators; existing formal scripts have it backfilled from the script plan by a migration.
- **Prompt authoring only adds the visual layer to storyboards pending authoring.** Its input is the formal script's own content fields; it no longer reads the script plan. By default it fills all entries pending authoring; `entry_ids` is kept as "explicitly rewrite these entries" and overwrites hand edits only when the user explicitly asks; `scope=all` is removed. The same applies to ad: manually added storyboards are set to pending authoring, and the same fill action supplies their prompts from the brief, product information and neighbouring storyboards; ad's one-click generation is unchanged.
- **Pending authoring is an explicit entry-level flag**, uniform across the four entry shapes segments / scenes / shots / video_units; it is set on materialisation and on manual addition, and cleared when authoring completes; drama / narration no longer infer it implicitly from "prompt is empty", and reference-to-video uses it to decide which units' body text still needs rewriting.
- **After confirmation, the script plan is read-only.** Web saves and the agent's `patch_draft` reject any confirmed script plan, prompting the user to make changes on the timeline; to redo the whole episode, re-run the script plan.
- **Content changes after authoring is complete are made on the formal script.** The timeline opens editing of `utterances` / `novel_text` / reference unit `text`; the corresponding source text is shown read-only, and reference units pass the script plan's `source_text` through into the formal unit; the agent can modify the corresponding source text via `patch_episode_script`, and when the project has source text the server validates that it is a verbatim substring of the source, consistent with the rule of the reference-to-video split tool.
- **Retired**: the entry fingerprint `script_plan_entry_revision` and the episode fingerprint `script_plan_revision`, entry currency comparison and merge assembly, backfill of existing data, `script_entry_currency` in `GET script-review`, the timeline banner 「内容已更新，提示词可能不符」 (Content updated; prompts may not match) and 「采用新内容」 (Adopt new content), conversion preview, and stale / removed entries of the formal script in workflow status. A project schema migration step deletes the existing fingerprint fields, materialises episodes that are "confirmed but without a formal script yet", and, for episodes that already have a formal script, stamps the pending-authoring flag on storyboards whose visual layer is empty.

## Considered Options

- **Keep the script plan authoritative and fold downstream structural edits back into the plan**: every add/remove entry point would have to modify both copies in the same transaction, the agent and reference-to-video paths would also have to be folded in, and we would need to decide "does a manual add/remove count as implicit confirmation of the new plan"; coupling would increase rather than decrease.
- **Keep fingerprints and partial re-runs as an optimisation**: after authoring is done the script plan is no longer modified, so partial re-runs have no trigger scenario; the only exception is redoing a whole episode, and that is exactly the case that does not need it.
- **Keep the old formal script as a backup and generate a new one on redo**: that brings back two sources of truth. The danger confirmation dialog is enough to prevent accidental clicks.
- **Open editing of the corresponding source text on the timeline**: editing the source anchor as free text very easily breaks it; read-only display plus writes through the agent with verbatim-substring validation already covers the need for re-anchoring.

## Consequences

- `docs/adr/0041`'s content/visual layering, pass-through and content confirmation remain in effect; its section on "plan as persistent substrate, entry-level increments, fingerprints" is superseded by this ADR. `docs/adr/0064` is not affected.
- `docs/adr/0041` specified that "free-text columns will henceforth only carry visual adaptation content (loss is tolerable)", and the drama projection accordingly treated the scene description as belonging only to the script plan and stripped it when converting into the formal script; that rule is superseded by this ADR: the scene description is carried over into the formal script on conversion, as a hidden input to prompt authoring.
- The agent documentation's guidance for content changes changes from "edit the plan and re-run authoring" to "`patch_episode_script` on the formal script"; "edit the plan and re-run" is used only to redo a whole episode; the `generate-script` skill's guidance on `entry_ids` and `scope` is rewritten along with the tool contract.
- The content confirmation page is read-only after confirmation and points to the timeline.
- The formal script, as an artifact, no longer uses the script plan as its basis for currency; a script plan that is re-run but not confirmed only shows up as content confirmation status and does not make the formal script stale.
- The glossary entries "entry currency" and "conversion preview" are deleted along with the retirement.
- Where the artifacts of old storyboards removed by an overwriting confirmation go follows the storyboard-removal rules: before the project trash lands, the artifacts are removed along with the storyboards and no longer shown; after it lands, they go to the trash.
