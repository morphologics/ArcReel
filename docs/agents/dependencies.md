# Adding and upgrading dependencies

1. **Write them with the package manager.** Backend: `uv add <package>` (add `--group dev` for dev dependencies); frontend and docs site: `pnpm add <package>` in their respective directories. Version numbers and lockfiles are written by the package manager, never by hand in `pyproject.toml` / `package.json`.
2. **Put them in a Dependabot group.** In `.github/dependabot.yml`, add the new package to the semantically closest group under `groups` for the corresponding ecosystem. `all-other` only collects unclassified packages and must not be used as the group for a new package; `uv run python scripts/audit_conventions.py --check` lists direct dependencies that only hit `all-other`.
3. **Run the dependency hygiene check.** `uv run deptry lib server alembic scripts tests`; if you changed a subpackage, also run `uv run deptry src tests` in that subpackage's directory (`packages/arcreel-market-core/`, `packages/arcreel-catalog-core/`). Third-party packages imported directly must be declared (`DEP003`), and packages declared but never imported must be removed or registered as runtime plugins (`DEP002`).

## Known version constraints

- **Frontend TypeScript is limited by the peer range of `typescript-eslint`.** Before upgrading TypeScript, check the peer range of the locked `typescript-eslint` version, and upgrade it in step if necessary.
- **The docs site's TypeScript is capped at 6.x.** The reason and the unlock condition are in the comment on the website section of `.github/dependabot.yml`.
- **The backend `anthropic` SDK is locked to 0.x.** 1.x switches its HTTP layer to `httpx2`: respx, used in tests (`tests/http_capture.py`), only intercepts `httpx`, and the way invocation endpoints rewrite request paths at the HTTP transport layer is also built on `httpx`, so neither works with 1.x. Unlock condition: respx supports `httpx2`, and the HTTP client and transport shared by the repository's Python invocation endpoints have migrated to `httpx2` (with SDKs such as `openai` migrating along with them).
- **The `version` fields in `pyproject.toml` and `frontend/package.json` are maintained by release-please** and are treated as read-only.
- **shadcn primitives are upgraded with dependencies.** Dependabot only upgrades npm packages and does not regenerate `frontend/src/components/ui/*.tsx`. Minor and patch upgrades of `@base-ui/react` and `shadcn` go into the `shadcn-stack` group; major upgrades get their own PR, in which `pnpm exec shadcn add <component> --diff` is run for each installed component, upstream changes are merged by hand, and local changes documented with comments are kept. When you hit a primitive defect, first use `add --diff` to check whether upstream has already fixed it.

- **Provider icons use only the standalone SVG entry points `@lobehub/icons/es/*/components/{Color,Mono}`.** A targeted override in `frontend/package.json` excludes that package's `@lobehub/ui` peer; these entry points depend only on React and do not use its UI components, which avoids automatically pulling in another set of UI and animation dependencies. If you switch to Avatar, combined entry points, or other components that depend on `@lobehub/ui`, re-check this constraint first.
